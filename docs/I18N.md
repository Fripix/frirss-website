# Ajouter une langue

1. Copier `src/i18n/en/` vers `src/i18n/<code>/`.
2. Ajouter une entrée à `src/config/locales.json` : `code`, `name`, `nativeName`, `dir` (`ltr` ou `rtl`), `ogLocale` (par exemple `de_DE`), `active: false`, `ready: false`.
3. Traduire les huit domaines (dont `reader.json`, qui reprend les libellés de l’interface FriRSS : utiliser ceux du fichier de traduction de l’application pour cette langue). Garder les clés, la forme des tableaux, les paramètres comme `{version}` et les identifiants techniques `link`. Les slugs de `seo.json` peuvent être localisés, sans accents ni espaces. Le slug de l’accueil reste vide.
4. Vérifier titres, descriptions, textes alternatifs, commandes contextuelles et sens de lecture avec une personne maîtrisant la langue.
5. Mettre `ready: true`, puis `active: true`, exécuter `npm run check`, `npm run build`, `npm test`. Une langue active mais non prête fait échouer les validations.
6. Générer la carte sociale de cette langue : `npm run social:images`. Le script, à lancer avec la prévisualisation de production sur le port 4322, capture le hero de l’accueil de chaque langue active. Aucun composant à changer.
7. Inspecter desktop et mobile, en particulier les titres longs et le RTL.

Le chargement des dictionnaires découvre automatiquement les dossiers JSON. Les types se déduisent de l’anglais. Le validateur compare toutes les clés terminales, les longueurs de tableaux, les paramètres, les valeurs vides et les marqueurs de travail. Il signale les domaines inconnus, slugs/titres dupliqués et groupes de messages inutilisés par les composants. Les champs internes d’un tableau sont vérifiés par typage et structure ; il ne s’agit pas d’une preuve formelle que chaque phrase est sémantiquement traduite.

Les contenus actifs sont complets : **aucun mélange silencieux avec l’anglais**. Le fallback est contrôlé au niveau de la publication : une locale non déclarée/active est inaccessible ; une traduction manquante dans une langue active fait échouer le build. Les ressources techniques liées sur GitHub peuvent être en anglais ou français ; leur langue est explicitée quand utile.

Les URL sont générées depuis l’identité de la page ; les menus et hreflang partagent la même source. L’utilisateur choisit sa langue, sans géolocalisation, redirection automatique de langue ni préférence persistante. Le nom de la marque, le slogan officiel, les noms des services, les commandes et les noms des thèmes FriRSS ne sont pas artificiellement traduits.

Les JSON UTF-8 par domaine sont compatibles avec une future intégration Weblate. Aucun service de traduction externe n’est configuré. Les textes de l’application ne sont pas synchronisés automatiquement avec le site.
